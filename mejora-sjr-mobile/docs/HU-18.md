# HU-18: Persistencia de sesión y componente de cámara

## Sesión

`TokenStorage.ts` es la única clase que conoce el mecanismo de almacenamiento. En Android e iOS
utiliza `expo-secure-store`; en web utiliza `localStorage`. `useSessionViewModel` depende de
`ITokenStorage`, recupera el JWT al montar la aplicación y expone tres estados:

- `restoring`: todavía no se decide qué navegación mostrar.
- `authenticated`: existe un JWT no vacío y se omite Login.
- `unauthenticated`: no existe JWT, falló la lectura o el ciudadano cerró sesión.

`App.tsx` crea una sola instancia de `TokenStorage`, la comparte con el servicio HTTP y la inyecta
al ViewModel. `AppRouter.tsx` muestra `SessionLoadingView`, las rutas públicas o las rutas privadas
según el estado. Al iniciar sesión, `useLoginViewModel` entrega el token a `startSession`; al cerrar
sesión, `signOut` elimina el valor persistido.

El Login quedó alineado con el backend actual: envía `{ Correo, Password }` y extrae el JWT desde
`{ success, message, data: { token, usuario } }`. La existencia local permite restaurar la sesión;
la autorización efectiva de cada operación continúa correspondiendo al backend.

## Cámara y galería

La responsabilidad se divide así:

- `models/PhotoFile.ts`: contrato estable que recibirá el código de multipart.
- `services/contracts/IImagePickerService.ts`: abstracción consumida por el ViewModel.
- `services/device/ExpoImagePickerService.ts`: permisos y llamadas a `expo-image-picker`.
- `viewModels/useCameraViewModel.ts`: carga, error, cancelación, selección y limpieza.
- `components/CameraSelector.tsx`: UI sin estado, permisos ni importaciones de ImagePicker.

El componente se conecta desde un adaptador o pantalla:

```tsx
const camera = useCameraViewModel(expoImagePickerService);

<CameraSelector
  photo={camera.photo}
  isLoading={camera.isLoading}
  error={camera.error}
  onTakePhoto={() => void camera.takePhoto()}
  onSelectFromGallery={() => void camera.selectFromGallery()}
  onRemovePhoto={camera.clearPhoto}
  onPhotoTaken={(file) => guardarEvidenciaSeleccionada(file)}
/>
```

`onPhotoTaken` recibe este contrato:

```ts
{
  uri: string;
  name: string;
  type: string;
  width: number;
  height: number;
  fileSize?: number;
  file?: File; // disponible en web
}
```

Para Android o iOS, Diana puede agregar la evidencia al `FormData` usando el nombre esperado por
el backend:

```ts
const formData = new FormData();
formData.append('evidencia', {
  uri: photo.uri,
  name: photo.name,
  type: photo.type,
} as unknown as Blob);
```

El destino actual es `POST /api/reportes/:id/evidencia`. El servicio de subida no forma parte de
HU-18; recibirá el archivo mediante inyección en la historia donde se implemente multipart.

## Pruebas manuales

1. Iniciar sesión, cerrar completamente la app y abrirla de nuevo: debe entrar a Home.
2. Pulsar `Cerrar sesión`, reiniciar la app y comprobar que aparece Login.
3. Montar `CameraSelector` con el ejemplo anterior y probar cámara y galería en un dispositivo real.
4. Denegar cada permiso y comprobar que aparece el mensaje correspondiente.
5. Cancelar el selector y comprobar que no se reemplaza una foto elegida previamente.

Después de cambiar la configuración nativa, detener Expo y volver a iniciarlo. Para un build propio
es necesario reconstruir la aplicación para aplicar los mensajes de permisos de `app.json`.
